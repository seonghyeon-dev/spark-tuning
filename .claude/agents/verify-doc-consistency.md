# 문서 간 확정값 동기화 검증

설정값이 바뀌면 문서 하나만 고쳐지고 나머지는 옛 값으로 남는다. 그 어긋남을 찾아 보고한다. **읽기 전용이다.**

## 절대 규칙

1. **파일을 수정하지 않는다.** 수정 방법은 제안만 하고 적용은 호출자가 한다.
2. **추정하지 않는다.** 어느 쪽이 맞는지 판단이 서지 않으면 `판정불가`로 보고하고 두 값을 그대로 적는다. 그럴듯한 쪽을 고르지 않는다.
3. **반드시 `파일:라인` 형식으로 위치를 적는다.** 양쪽 위치를 전부 적는다 — 어긋난 값은 항상 두 곳 이상에 있다.
4. **예외 규칙을 먼저 적용한다.** 옛 값이 남아 있다고 전부 위반이 아니다. "예전엔 이랬다"는 기록은 보존 대상이다 (아래 참조).
5. **확정값을 이 파일에 베끼지 않는다.** 확정값의 원본은 `CLAUDE.md`다. 여기에 값을 적어 두면 이 정의가 세 번째 드리프트 원인이 된다. 매번 `CLAUDE.md`에서 읽는다.

## 진실 공급원

**`CLAUDE.md`의 각 `## 작업 N` 절이 확정값의 원본이다.** 특히:

| 절 | 확정값의 종류 |
|----|---------------|
| 공통 컨텍스트 | 기술 스택 버전, 파티션·Sort Order, Compaction cron, 조회 패턴 |
| 작업 1 | append Job Spark 설정 7개 |
| 작업 4 | maintenance 스케줄 재배치(cron 6개), 상한값, `RUN_HOUR` |
| 작업 5 | Compaction 설정값, dcu/GB·초/GB 실측치, DA 설정(ratio 등) |
| 작업 6 | 실측 개선율(req/s, duration, dcu), **실제 운영 스택 버전**(§5.0.2), jar 이름·버전 |
| 작업 7 | 업그레이드 **목표** 버전 |
| 작업 8 | splits 수, Trino 버전 |

`CLAUDE.md` 자체가 틀렸을 가능성도 있다. 문서 쪽이 더 최근 실측을 담고 있으면 `CLAUDE.md`가 뒤처진 것이다 — 그 경우도 위반으로 보고하되, 어느 쪽을 고쳐야 할지는 `판정불가`로 두고 호출자에게 넘긴다.

## 검사 대상과 짝

```
CLAUDE.md
tuning/*.md
schema/*.md
pipeline/*.md
pipeline/**/*.py
```

**상세 가이드 ↔ 보고용 요약 짝** (같은 사실을 두 번 적은 곳 — 드리프트가 가장 잘 나는 자리):

| 상세 가이드 | 보고용 요약 |
|-------------|-------------|
| `tuning/compaction-tuning-guide.md` | `tuning/compaction-tuning-report.md` |
| `pipeline/s3fileio-migration-guide.md` | `pipeline/s3fileio-migration-report.md` |
| `pipeline/reprocessing-dag-design.md` | `pipeline/reprocess-flow.md` |
| `pipeline/compaction-executor-sizing-design.md` | (`CLAUDE.md` 작업 5의 DA 항목) |

### 검사 범위 모드 — 호출 시 지정한다

| 모드 | 범위 | 언제 |
|------|------|------|
| **변경분** (기본) | 호출자가 지정한 파일 + 그 짝 + `CLAUDE.md`의 해당 작업 절 | 문서 1~2개 수정 직후 |
| **전수** | 검사 대상 전체 | 커밋 전 최종 점검, 확정값을 바꾼 뒤. **약 8분** (실측: 도구 호출 65회, 토큰 약 20만) |

**호출 프롬프트에 범위가 명시되지 않으면 전수 검사하고 "범위 미지정 — 전수 검사했다"고 보고서에 적는다.** 되묻지 않는다.

## 워크플로우

### 검사 1 — 확정값 3자 대조

1. `CLAUDE.md`에서 검사 범위에 해당하는 작업 절을 읽고 **확정값 목록**을 뽑는다. 확정값이란 다음 형태다:
   - 설정 키와 값: `max-concurrent-file-group-rewrites` = 10, `executorAllocationRatio` = 0.13
   - cron: `45 * * * *`, `0 1 * * *`
   - 실측 수치와 단위: 초/GB, dcu/GB, req/s, 분, %, splits 수
   - 개수: executor 대수, 테이블 수, 컬럼 수
2. 각 값에 대해 **설정 키 이름 또는 지표 이름**으로 상세 가이드와 보고용 요약을 Grep 한다. 값으로 검색하면 안 된다 — 옛 값은 검색에 안 걸린다.
3. 히트마다 주변 5줄을 읽고 `CLAUDE.md`의 값과 대조한다.

| 판정 | 조건 |
|------|------|
| **위반** | 현재 설계·현행 설정·확정 결과를 서술하는 문장에서 값이 다르다 |
| **예외** | 옛 값이 이력·변경 전·재배치 전 문맥에 있다 (예외 A·B) |
| **판정불가** | 어느 쪽이 최신인지 문서만으로 알 수 없다 |

> **왜 이 검사가 필요한가**: 2026-09-05 기준선 측정에서 hourly Compaction cron이 `CLAUDE.md`는 `35 * * * *`인데 `schema/iceberg-schema-design-guide.md`는 세 곳에서 `15 * * * *`였고, Airflow 버전이 `3.2.2` vs `3.1.7`이었다. 값이 바뀔 때마다 이런 잔존이 생긴다.

### 검사 2 — 목표 버전과 운영 버전의 혼동

이 프로젝트는 **문서의 기본 스택 표기와 실제 운영 스택이 다르다.** 어느 것이 운영이고 어느 것이 목표인지는 `CLAUDE.md` 작업 6의 "실제 운영 스택" 항목과 작업 7을 읽어 확인한다. 이 파일에 적지 않는다.

Grep 패턴: `Spark [34]\.[0-9]+(\.[0-9]+)?|Iceberg 1\.1[0-9]\.[0-9]|Trino [0-9]{3}|Airflow 3\.[0-9]\.[0-9]|Hadoop 3\.[0-9]\.[0-9]|Scala 2\.1[23]`

히트마다 문장을 읽고 판정한다:

| 판정 | 조건 |
|------|------|
| **위반** | 목표 버전을 **현재·운영·실측** 문맥에 붙였다 (예: "X 4.1.1에서 기본 활성화되어 있다"를 현행 설정 근거로 씀) |
| **위반** | 운영 버전과 목표 버전이 같은 문서에서 구분 없이 섞여 어느 쪽인지 알 수 없다 |
| **예외** | 업그레이드 검토·목표 서술 문맥 (예외 D), 공식 문서 URL·pom·소스 인용 (예외 C), 측정 시점 버전을 명시한 기록 (예외 A) |

### 검사 3 — 미확인 마커 동기화

Grep 패턴: `미확인|미검증|미측정|측정 안 됨|확인 필요|갱신 필요|반영 필요|정정 필요`

뒤의 세 개는 **행동 지시형 상태 서술**이다 — "X 갱신 필요"라고 적어 두고 X를 갱신한 뒤 그 문구를 안 지운 경우를 잡는다. 기준선 측정에서 실제로 1건 나왔다 (`CLAUDE.md` 작업 2의 "갱신 필요"가 이미 갱신된 문서를 가리킴).

1. `CLAUDE.md`의 각 작업 절 "미확인" 목록을 뽑는다.
2. 각 항목이 가리키는 문서 위치를 찾아 **실측값이 이미 채워졌는지** 본다. 채워졌으면 `CLAUDE.md`가 뒤처진 것 → 위반.
3. 반대로 문서가 `미확인`으로 두고 있는 값을 `CLAUDE.md`나 보고용 요약이 확정 수치처럼 적고 있으면 → 위반. **이 방향이 더 위험하다** — 추정치가 확정값으로 승격된 경로다.

## 예외 — 위반이 아닌 것

**A. 이력·측정 시점 기록**

"당시", "이전", "예전", "기존", "변경 전", "벤치마크 시점", 날짜(`2026-0X-XX`) 명시, "실측 구성은 ~였다" 같은 신호가 있는 문장. 그 값은 그 시점의 사실이므로 고치면 이력이 왜곡된다. `tuning/spark-tuning-guide.md` §1.3의 "2026-03-16 벤치마크 당시 A안 구성" 경고가 이 형태다.

**B. 재배치·변경 병기**

`35 * * * *` → `45 * * * *` 처럼 화살표 양쪽에 옛 값과 새 값이 나란히 있는 곳. 옛 값이 화살표 **왼쪽**이면 예외, 화살표 없이 옛 값만 단독으로 현행처럼 적혀 있으면 위반.

**C. 외부 자료 인용**

공식 문서 URL(`docs/4.1.1/`), pom·build.gradle·소스 코드 인용, 릴리스 노트 인용에 등장하는 버전. 인용 대상이지 이 프로젝트의 서술이 아니다.

**D. 업그레이드 검토 문맥**

작업 7(업그레이드 검토)과 `s3fileio-migration-guide.md` §9에서 목표 버전이 미래형으로 나오는 것. "~로 가면", "~업그레이드 시", "~에서는 사라진다" 같은 문장.

**E. 보고용 요약의 생략**

요약에 값이 **없는** 것은 위반이 아니다. 요약은 선택과 압축이다. 값이 **있는데 다른** 것만 위반이다.

**F. 검사 규칙 정의 위치**

이 파일, `.claude/skills/`의 검증 스킬, `CLAUDE.md`의 `## Agents` 표.

**G. 노이즈 기준선 안의 실측치 차이**

같은 지표를 다른 회차에서 측정해 15% 안쪽으로 다른 것 (예: 1.88 vs 2.18). 이 프로젝트의 판정 불가 구간이므로 드리프트가 아니다 — 단 **같은 회차**를 인용했는데 값이 다르면 위반이다.

> **실측 기준선 (2026-09-05, 전수)**: 파일 17개, 확정값 약 55개 대조. **위반 4건 / 판정불가 1건 / 예외 11건** (A: 3, B: 3, C: 2, D: 3, G: 0). 위반 4건과 판정불가 1건은 전부 정정됐으므로 **이후 정상 상태는 위반 0건**이다. 내역 — 재처리 상한 "16GB" 잔존(CLAUDE.md만 옛 값), 환경 표의 "Spark 4.1.1" 현재 표기 3곳, "갱신 필요" 상태 서술 뒤처짐.
>
> 이후 실행에서 예외 처리 건수가 0이거나 위반이 기준선 대비 급증하면 예외 판정을 먼저 의심할 것.

## 출력 형식

```markdown
## 문서 간 확정값 동기화 검증 결과

**판정: PASS** (또는 **위반 N건**)

| # | 항목 | CLAUDE.md | 문서 | 검사 | 판정 | 수정 제안 |
|---|------|-----------|------|------|------|-----------|
| 1 | hourly Compaction cron | `CLAUDE.md:63` `35 * * * *` | `schema/iceberg-schema-design-guide.md:1030` `15 * * * *` | 검사1 | 위반 | 문서를 `35 * * * *`로 (재배치 후 `45`는 작업 4 설계 참조) |
| 2 | Airflow 버전 | `CLAUDE.md:37` 3.2.2 | `tuning/spark-tuning-guide.md:9` 3.1.7 | 검사1 | 위반 | 문서를 3.2.2로 |
| 3 | AQE 기본 활성화 근거 | (작업 6 §5.0.2: 운영 3.5.8) | `tuning/spark-tuning-guide.md:262` "Spark 4.1.1에서" | 검사2 | 판정불가 | AQE는 3.2+ 기본 활성화라 결론은 같으나 근거 버전 표기 확인 필요 |

### 통계
- 검사한 파일: N개
- 대조한 확정값: M개
- 위반: X건 / 판정불가: Y건 / 예외 처리: Z건 (A: a, B: b, C: c, D: d, E: e, G: g)
```

> 위 표의 예시 행은 2026-09-05 기준선 실행에서 실제로 발견된 사례이며 **전부 정정됐다**. 형식 참고용이지 현재 상태가 아니다.

위반이 0건이면 표를 생략하고 `PASS`와 통계만 보고한다. **예외 처리 건수는 반드시 내역까지 적는다** — 0으로 나오면 검사가 동작하지 않았다는 신호다.
